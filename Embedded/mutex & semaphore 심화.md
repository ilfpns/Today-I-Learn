---

동기화 : 여러 실행 주체가 자원을 사용할 때, 실행 순서와 접근 타이밍을 의도대로 맞추는 것

임계영역 : 프로세스에서 공유 데이터를 접근하는 코드 블록

락 : 어떤 자원을 쓸 때, 다른 프로세스의 대기를 강제함

lock을 가지다 : 자원에 나만이 접근할 수 있다

상호배제 : 특정 프로세스만 진입하여 실행이 가능하다 

Mutex & Semaphore : 상호배제를 동기화 기법으로 구현한 것 

Non-busy-wait : 자원을 점유하기 전까지 CPU를 내려놓고 기다림

> **Mutex**
> 

---

⇒ 공유된 자원의 데이터 혹은 임계영역 등 하나의 프로세스 혹은 스레드가 접근하는 것을 막아줌

⇒ 동기화의 대상이 하나다 (뮤텍스가 보호하는 자원이 하나이다)

⇒ 임계영역을 가진 스레드들이 겹치지 않고 각각 단독으로 실행하는 기술

**프로세스 접근 방법**

- 뮤텍스 객체가 잠김/열림 상태를 가짐
- lock에 성공한 스레드가 소유권을 가짐

⇒ 리소스에 대한 접근을 조율하기 위해 동기화 또는 락을 사용함

- Mutex를 소유한 자원만이 lock을 해제할 수 있음

> **Semaphore**
> 

---

⇒ 공유된 자원의 데이터 혹은 임계영역 등에 여러 프로세스 혹은 스레드가 접근하는 것을 막음

⇒ 동기화의 대상이 하나 이상이다 (여러개의 동시 접근을 허용)

- 공유 자원에 접근할 수 있는 프로세스의 최대 허용치만큼 동시에 접근이 가능하다
- 자원이 프리하다면 다른 프로세스가 바로 사용할 수 있다
- 일반적으로 비교적 긴 시간을 확보하는 리소스에 대해 사용한다

**Semaphore의 정수**

- Semaphore는 하나의 정수를 가짐
- 예를 들어 3을 가졌을 때, 최대 3개의 프로세스가 자원에 접근할 수 있다
- 공통의 자원에 접근하는 프로세스를 제어

> **차이점 & 공통점**
> 

---

1. Mutex는 하나의 임계 영역에 대한 상호 배제를 제공하고 Semaphore는 동일한 자원의 동시 접근 개수를 제어함 [차이점]

1. Mutex는 자원을 소유할 수 있고 Semaphore는 그렇지 않다 [차이점]

| 구분 | Mutex | Semaphore |
| --- | --- | --- |
| 주 용도 | 임계 영역 보호 | 자원 개수 관리 / 이벤트 |
| 소유권 | 있음 | 없음 |
| 우선순위 상속 | 있음 | 없음 (보통) |
1. Non-busy-wait 기법을 사용한다 [공통점]

> **Mutex & Semaphore 만으로 해결할 수 없다**
> 

---

⇒ 부족한 부분이 있는 개념들로 데드락을 대처할 수 없음

⇒ 동시성 제어 전략이 추가로 필요함

1. 락 계층화 (Lock Ordering)
    
    ⇒ 락 획득 순서 고정
    
    ```c
    항상 A → B 순서로만 lock
    ```
    

1. 타임아웃 락 (Try-lock / Timed-lock)
    - 무한 대기 방지
    - 데드락 회피
    
    ```c
    if (pthread_mutex_trylock(&m) == 0) {
       ...
    }
    ```
    

1. 조건 변수 (Condition Variable)
    - 상태 기반 동기화
    
    ```c
    while (!ready)
        pthread_cond_wait(&cond, &mtx);
    ```
    

1. 우선순위 상속 & 천장 
    - **Priority Inheritance**
    - **Priority Ceiling Protocol**
    - 우선순위 역전 해결
