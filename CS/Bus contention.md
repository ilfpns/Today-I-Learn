> **Bus Contention**
> 

---

⇒ 여러 장치가 하나의 버스를 사용하려고 할 때 발생하는 충돌 현상

⇒ 접근 권한 경쟁

⇒ 여러 마스터가 하나의 버스를 쓰려고 권한 경쟁을 벌이는 상태

- System Bus는 CPU, 메모리, I/O 장치 등 여러 장치가 데이터를 전송하기 위해 공유함 ⇒ 다른 장치가 사용하면 다른 장치는 대기

- 속도 저하 발생 가능
- 성능 저하 발생 가능

### 발생 조건

1. 단일 System Bus, 단일 메모리 버스
2. CPU코어, DMA, GPU, NIC, USB 컨트롤러 등 많은 마스터가 존재
3. 같은 시점에 접근 요청 발생

### 발생 원리

일반적으로 컴퓨터는 특정 장치가 버스를 사용할 권한을 요청하는

- 버스 요청 (Bus Request)
- 버스 허가 (Bus Grant)

로  충돌을 방지한다

### 미치는 영향

1. 데이터 전송 지엽
    
    ⇒ 하나의 장치만이 사용하기에 데이터 전송량이 많을 때 지연될 수 있다
    
2. 성능 저하 
    
    ⇒ 성능이 저하될 수 있고, 응답이 중요한 앱에서 장애 발생 가능
    
3. 버스 효율 저하 
    
    ⇒ 버스 사용 효율이 낮아지며 시스템 자원의 비효율적 활용이 발생할 수 있다
    

### 해결 방법

1. Arbitration (중재)
    
    ⇒ 버스를 사용할 수 있는 우선순위를 정한다
    
2. Bus Segmentation (버스 분할)
    
    ⇒ 여러 개의 독립된 버스를 만들어, 각 버스가 서로 다른 장치를 담당하도록 함
    
3. Time Multiplexing (시간 분할 방식)
    
    ⇒ 특정 시간 동안 한 장치만 버스를 사용하도록 함
    
4. Point to point Interconnect
    - PCle
    - Noc
    
    ⇒ 공유 버스 제거
    
    ⇒ 스위치 기반 라우팅
    
    ⇒ 동시 전송 가능가
    

### PCle

```cpp
           ┌── Device A
CPU ── Switch ── Device B
           └── Device C
```

**스위치**

1. 스위치는 CPU가 준 주소를 확인하고, 이에 맞는 포트로 전송
2. EndPoint(A, B, C)가 보낸 패킷도 주소를 스위치가 보고 CPU에게 전달

**특징**

- 장치마다 전용 link가 존재
- 동시에 여러 장치가 전송 가능하다
- 포워더이다

### 패킷 ID

⇒ 패킷은 항상 ID가 있음

- Upstream : Device가 보낸 패킷
- Downstream : CPU가 보낸 패킷

- Register ID : 누가 요청했는지
- Completer ID : 누가 응답해야 하는지
